# HPC & GPU 인프라 핸드북

클러스터 구성부터 스케줄링, 성능 튜닝, 장애 분석까지 다루는 실무 문서다.

**사이트:** https://johklo.github.io/hpc-gpu-curriculum/

## 구성

| 모듈 | 주제 |
| --- | --- |
| 01 | HPC 기초. 클러스터 구성, 스케줄러의 역할, Slurm 구조와 명령, MPI |
| 02 | 클러스터 운영. 노드 점검, 메모리와 스토리지, 사용자 환경, 로그, GPU 자원, 모니터링 |
| 03 | Linux 성능 튜닝. NUMA 배치, 메모리 설정, I/O 스케줄러, 네트워크, 다수 노드 실행 |
| 04 | 스케줄링. 토폴로지 인지 배치, 갱 스케줄링과 백필, 공정 배분, 전력, 하이브리드 |
| 05 | ML 오케스트레이션. Slurm과 Kubernetes 비교, 분산 학습 실행, 체크포인트 |
| 06 | 하드웨어 점검과 장애 분석. PCIe, NVLink, Xid, DCGM, 성능 저하 진단 |

## 고치는 법

사이트의 문서 제목 옆 **고치기**를 누르면 GitHub 편집 화면이 열린다. 고쳐서 저장하면
변경 이력이 남고, 워크플로가 사이트를 다시 만든다.

문서는 `content/` 아래 Markdown 파일이다. 파일 하나가 모듈 하나이고, `## ` 제목이 왼쪽
목차의 항목이 된다. 앞부분 머리말에서 번호와 난이도를 정한다.

```markdown
---
id: m1-foundations
no: "01"
title: HPC 기초
subtitle: 클러스터의 구성과 작업 실행 경로
level: 입문
---

모듈 도입부.

## 첫 번째 절
본문.
```

그림은 `assets/img/`의 SVG를 쓰고 `![설명](img/파일명.svg)`으로 넣는다. 모두 직접 그린
것이다.

## 빌드

```bash
pip install markdown
python build.py        # content/*.md -> site/
```

## 어투

문서는 `-다` 평서형으로 쓴다. 존댓말과 1인칭을 쓰지 않고, 과장 형용사와 요약 라벨을 넣지
않는다.
